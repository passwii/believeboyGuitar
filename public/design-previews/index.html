站点前端重设计：先定结构，再定气质

这一轮不改任何站点代码。下面是现状盘点、竞品考察、一套信息架构提案， 以及三个视觉方向的完整预览（桌面 + 手机 PWA）。每个方向都是可以直接点开看的静态页面。

纯静态预览，站点代码零改动 2026-10-24 覆盖：首页 / 资料库 / 工具间 / 节拍器 / 手机 PWA

现状盘点：混乱从哪里来

把现有站点过一遍，「乱」不是样式问题，是结构问题。逐条列出来：

  1. 1

    首页混了三件不相关的事。 定位语、学习目标、最近整理、五个工具列表全部纵向堆在一页里，彼此没有视觉分区，扫一眼抓不到重点。

  2. 2

    工具的地位不一致。 节拍器独占主导航入口，其余四个工具（速查表、和弦库、练习计划、节奏型）只能从首页列表深处进。五个工具明明是同一类东西，却有两套待遇。

  3. 3

    「读」和「用」两种模式没有分开。 资料是拿来读的（长文、目录、筛选），工具是拿来用的（全屏、大控件、即时反馈）。现在两者共用同一套页面外壳，工具页被导航和页脚夹着，不像一个「仪器」。

  4. 4

    手机上的层级不统一。 资料库的筛选收在结果下面、工具入口埋在首页第四屏、节拍器又是全屏页。同样一件操作（「找东西」），在不同页面要走不同的路径。

  5. 5

    PWA 装完之后没有「应用感」。 安装后落地在节拍器（这点是对的），但站内导航、返回路径还是网页逻辑；长按图标只有一个快捷方式；工具页的离线与全屏体验没有推广到全部工具。

竞品考察：值得借的做法

用浏览器实际过了一遍同类站点（工具站 + 个人信息管理站），记下结构层面的做法，只借思路不搬样式。

Songsterr

曲谱工具站 · 工具型参考

  • 工具即首页：打开就是可用的播放器与搜索，没有营销层。
  • 移动端常驻底部 dock，六个高频操作永远在同一位置，像原生 App。
  • 列表行只有「曲名 + 艺人 + 难度点」，密度高但不乱。

Raindrop.io

书签管理站 · 个人信息管理参考

  • 「集合（分组）+ 列表 + 筛选」是稳定骨架，所有内容在这套骨架里流动。
  • 搜索与筛选永远在内容上方一屏内，先给结果再给工具。
  • 空状态与计数做得诚实：有多少、缺什么，一眼可见。

mymind

个人收藏库 · 气质参考

  • 个人库不需要营销首页：定位语一句话讲完，气质全部来自排版与秩序。
  • 「不组织也是一种组织」：靠搜索和自动分组降低维护负担，和我们「manifest 唯一事实来源」的思路同源。
  • 衬线大标题 + 大量留白，证明工具站也可以有编辑气质。

PWA 通用模式

Apple / Google 官方指引

  • 独立窗口 + 底部安全区 tab 栏，是移动 PWA 的标准外壳。
  • manifest shortcuts：长按桌面图标直达高频功能（现有 manifest 只配了资料库一个）。
  • 离线外壳优先：工具页先做到断网可用，内容页次之。

信息架构提案：书房 × 工具间

三个方向共用同一套结构骨架（这也是节拍器「独立开来」思路的推广）： 把「读资料的房间」和「用工具的房间」分开，各有各的外壳和导航。

书桌（入口）

/

首页瘦身为「继续整理 + 学习目标」两件事，工具入口压缩成一行横排入口条，让给内容。

书房（读模式）

/library

全部资料：搜索、筛选、列表。桌面右栏留目录位，移动端保持「先看结果」。

/library/<slug>

阅读页。现状问题不大，换外壳即可。

工具间（用模式）

/tools

新增工具 hub，五个工具一律平等，从这里进。

/tools/metronome

全屏仪器式外壳，无页脚、无正文干扰，控件按拇指热区排布。

/tools/*

速查表 / 和弦库 / 练习计划 / 节奏型，同样外壳。

导航随之简化

桌面：站名 + 「资料」「工具」两个入口，节拍器的特殊待遇取消（它从 dock 和快捷方式获得更直接的入口）。 手机：顶部只留站名，导航整体下沉为底部 dock（首页 / 资料 / 工具 / 节拍器），带安全区避让。 这是移动 PWA 最像原生 App 的一步。

三个视觉方向

结构一致，气质不同。点开任何一个都是完整的多页预览（首页、资料库、工具间、节拍器、手机 PWA）。

纸上琴房
方向 A · 演进

纸上琴房

保留现在的暖纸面与衬线气质，只修结构：首页分区、工具统一外壳、移动端 dock。风险最小，气质延续。
舞台侧
方向 B · 重做

舞台侧

暗色仪器面板：工具是主角，琥珀色单强调色，移动端原生 App 式 dock。PWA 安装后最像「一个应用」。
工作台面板
方向 C · 重做

工作台面板

冷白精工风：网格、发丝线、等宽数字、电蓝单强调色。工具像仪器面板，资料像技术手册，精确冷静。

移动端 PWA 适配清单

无论选哪个方向，以下适配都做。现有基础（manifest、Service Worker、安装提示、安全区）保留并扩展。

  • 底部 dock 导航移动端导航下沉到底部，四项（首页 / 资料 / 工具 / 节拍器），44pt 触控目标，env(safe-area-inset-bottom) 避让，PWA 独立窗口与浏览器里同样成立。
  • 工具统一外壳全部工具页去掉正文页脚与面包屑，控件置底、结果置顶，全部达到节拍器现在的全屏标准；断网可用列入验收。
  • manifest shortcuts长按桌面图标直达：节拍器（已默认）、和弦库、速查表、节奏型。现在只配了资料库一个，全部补齐。
  • start_url 策略保持 /tools/metronome 不变：安装这个应用的主要场景是练琴，打开即出声。读资料的场景走 dock，两不耽误。
  • iOS 细节apple-web-app-title 从「节拍器」改回站名（现在全站装到桌面都叫节拍器，是历史遗留）；状态栏样式随方向定；启动画面色与 canvas 同源。
  • 离线分层第一层：外壳 + 全部工具页预缓存（练习时可能没网）；第二层：访问过的资料页缓存；标签页 / 元数据本就静态，天然离线。
  • 不做的推送通知、进度统计、账号云同步仍不做（与 CLAUDE.md 的「刻意不做」一致）。

需要你拍板的事

  1. 三个方向选哪个？也可以混搭（例如 A 的纸面 + B 的移动端 dock，两者不冲突）。
  2. 工具路由迁到 /tools/* 吗？迁的话旧路径用 Vercel 重定向兜底，收藏夹不失效。
  3. 首页保留「学习目标」区块吗？它和「最近整理」哪个更常看？这决定书桌页谁是第一屏。
  4. 暗色（方向 B）如果落选，是否接受「仅工具页局部暗色画布」的折中（现在的指板已经是这个做法）？
