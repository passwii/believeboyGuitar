这个资料库解决什么问题

收集来的资料本身不是学习成果。PDF、截图、零散的笔记往往结构混乱、重点不明， 每次想复习都要重新翻一遍。这个资料库承担的是一次性的整理工作：把原始资料 提炼、重组、改写成结构清晰、可以直接阅读的内容，之后只需要读整理后的页面。

原始资料是输入，改写后的页面才是资产。

内容是怎么组织的

每篇内容由两部分构成：一个只放正文的 HTML 文件，以及清单里的一条记录。 正文文件不写样式、不写导航，样式全部由网站统一提供，这样视觉上不会走样。

清单里每条记录的字段含义：

字段 含义
slug 唯一标识，决定正文文件名与访问地址
title / summary 标题与一句话简介
stage 学习阶段：入门、基础、进阶
topics 所属主题，用于资料库筛选
tags 自由标签，参与搜索
difficulty 难度，1 到 5
source 来源出处与版权说明
updatedAt 最近整理时间

指板图这类交互内容怎么放

音阶图、和弦图这类光靠文字说不清的内容，正文里只写一个占位标记：

<lesson-widget name="组件名"></lesson-widget>

标记放在哪个位置，组件就渲染在哪里。具体画成什么样由网站代码决定， 正文依然只有语义标签，不带样式也不带脚本。可用的组件名登记在 content/widgets.ts，构建期的校验会拦住写错的名字。

新增一篇资料的流程

  1. 把原始资料放进 inbox/。这个目录不纳入版本库。
  2. 先对内容结构达成一致：打算怎么分节、哪些地方不确定、哪些结论需要核对。
  3. 确认后生成 content/lessons/<slug>.html，并在清单里登记一条记录。
  4. 浏览器打开实际页面，确认排版正常、内容没有走样。
  5. 原始资料移到 archive/。

哪些内容必须人工核对

改写是结构重组与语言重写，不是逐字翻译。涉及指法、音阶图、和弦图 这类错一个音就会练错的内容，必须逐条核对原始资料后再采用。

为什么第一版刻意做得很小

个人资料库真正的失败模式不是功能少，而是整理了几篇之后就不再更新。 所以第一版不做打卡、进度统计、复习提醒，也不做账号与云同步。 等实际用一段时间、确认真实需要了再加。
