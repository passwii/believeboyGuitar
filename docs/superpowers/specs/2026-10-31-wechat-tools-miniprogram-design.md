# 微信工具型小程序 — 设计规格

日期：2026-10-31
状态：待用户 review
范围：微信原生小程序第一版，只包含节拍器与调音器

## 1. 目标

把现有 PWA 中成熟的节拍器体验迁移到微信小程序，并新增一个可实际使用的吉他调音器。第一版是独立工具，不承载首页、周练和资料库内容。

成功标准：

- 节拍器在前台连续运行 15 分钟，无累积漂移、无旧参数漏音，锁屏或切出微信后停止而不是假播放。
- 调音器能在微信开发者工具、至少一台 iPhone 和一台 Android 真机上完成麦克风授权、自动识别、手动锁弦和音分显示。
- 纯逻辑有自动化测试，麦克风、音频播放、权限与真机行为有明确的人工验收步骤。
- Web 现有功能不被破坏，`content/manifest.ts` 仍是内容目录的唯一事实来源。

## 2. 范围

### 做

- 微信原生小程序：TypeScript、WXML、WXSS。
- 底部两个 Tab：节拍器、调音器；默认进入节拍器。
- 节拍器对齐当前 PWA：30–240 BPM、六种拍号、三种音色、圆盘调速、±1 BPM、拍点高亮、屏幕常亮。
- 调音器：自动识别、手动锁弦、标准调弦、Drop D、降半音、半音阶模式。
- 可共享的纯 TypeScript 核心逻辑与测试。
- 错误状态、权限处理、页面隐藏时停止音频与录音。

### 不做

- 微信以外的支付宝、抖音等小程序平台。
- Web 首页、周练、资料库内容迁移。
- 账号、云同步、后端、数据库、云函数。
- 练习记录、统计、提醒、分享排行。
- 锁屏或切出微信后持续播放。
- 参考音播放、节拍器 Tap tempo、自定义拍号、自定义调弦。
- 暗色模式。
- 用 Taro、uni-app 或 `web-view` 包现有站点。

## 3. 关键约束

- 只发布微信小程序，使用微信原生开发。
- 基础库最低版本为 2.19.0，因为节拍器依赖 `wx.createWebAudioContext()`。
- 节拍器只保证小程序在前台时的声音与调度；页面隐藏时立即停止并释放音频。
- 调音器只在小程序前台录音；页面隐藏时停止录音并结束本次调音。
- A4 固定为 440 Hz，第一版不提供参考频率调节。
- 不把小程序 UI 代码与 Web React 组件强行共享；共享规则、算法、调弦数据和视觉令牌。
- 媒体采集、音频播放和设备会话等底层 API 放在 `miniprogram/adapters/`；页面可以直接调用权限与设置、提示弹窗、屏幕常亮和页面生命周期相关的微信 API。共享纯逻辑不得引用 `wx`、DOM、React 或 Next。

## 5. 共享核心接口

`packages/guitar-core` 只能包含平台无关的 TypeScript。

### 5.1 节拍器

从现有 `lib/metronome.ts` 迁移并保留已测试的行为：

- `METERS`：4/4、3/4、2/4、6/8、5/4、7/8。
- `BPM_MIN = 30`、`BPM_MAX = 240`、`BPM_DEFAULT = 90`。
- `clampBpm()`、`bpmToIntervalMs()`、`tempoName()`、`nextBeat()`。
- `bpmToDialAngle()`、`dialAngleFromPoint()`、`dialPointToBpm()`。
- `pickResumeClick()` 与 `retainScheduleWindow()`：保留给现有 Web 和未来扩展，微信第一版只使用开始/停止，不启用暂停。

核心只负责计算，不创建定时器、不访问音频上下文。

### 5.2 调弦

```ts
type StringTarget = {
  id: "6" | "5" | "4" | "3" | "2" | "1";
  label: string;
  note: string;
  octave: number;
  frequency: number;
};

type TuningPreset = {
  id: "standard" | "drop-d" | "half-step-down";
  label: string;
  strings: readonly StringTarget[];
};
```

第一版调弦数据：

| 预设 | 六弦到一弦 |
| --- | --- |
| 标准 | E2 82.4069、A2 110、D3 146.832、G3 195.998、B3 246.942、E4 329.628 |
| Drop D | D2 73.4162、A2 110、D3 146.832、G3 195.998、B3 246.942、E4 329.628 |
| 降半音 | Eb2 77.7817、Ab2 103.826、Db3 138.591、Gb3 184.997、Bb3 233.082、Eb4 311.127 |

音分统一按 `1200 * log2(measured / target)` 计算。显示四舍五入到整数音分。

### 5.3 音高检测

`pitch.ts` 提供一个无依赖的单音检测器：

- 使用 4096 个 Float32 采样帧。
- 使用 McLeod Pitch Method（MPM）检测基频与清晰度；算法参考 Pitchy 4.1.0（0BSD），在小程序内保留来源说明。
- 输入范围限制为 55–400 Hz，覆盖降半音低音弦到高音 E，并为音高偏移留出余量。
- 输出 `{ frequency, clarity, rms }`。
- 频率或清晰度无效时返回 `null`。

音高检测器不依赖采样率固定值，调用方必须传入实际采样率。

## 6. 小程序导航与布局

`app.json` 使用原生 `tabBar`：

| 顺序 | 页面 | 文案 |
| --- | --- | --- |
| 1 | `pages/metronome/index` | 节拍器 |
| 2 | `pages/tuner/index` | 调音器 |

打开小程序默认进入节拍器。两页都使用微信原生导航栏，不套用 Web 站点的顶部导航或底部 dock。页面内容避开底部安全区。

全站沿用现有浅色视觉语言：

- 画布 `#F1F2EC`，面板 `#FBFCF8`，主文字 `#1D2520`，强调色 `#267B55`。
- 字体使用微信系统字体栈；数字使用等宽数字。
- 触摸目标不小于 44px，节拍器主按钮不小于 64px。
- 不使用外部字体、图片大背景或暗色模式。

## 7. 节拍器

### 7.1 页面结构

```text
┌───────────────────────────┐
│ 拍号 4/4      准备开始     │
│ [1][2][3][4]              │
│                           │
│         ╭───────╮         │
│         │  90   │         │
│         │Andante│         │
│         ╰───────╯         │
│                           │
│ [拍号]     [开始]    [音色] │
└───────────────────────────┘
```

- 顶部显示当前拍号和运行状态。
- 拍块数量由拍号决定；当前拍整块换成强调色。
- 中部圆盘占剩余高度，显示 BPM 和速度术语。
- 底部三个主操作：切换拍号、开始/停止、切换音色。
- 拍号与音色按钮点击后循环到下一项，并显示当前值。
- 主按钮在 `idle` 显示“开始”，在 `running` 显示“停止”。

### 7.2 状态与行为

微信第一版只有两个状态：`idle` 和 `running`。

| 动作 | 当前状态 | 结果 |
| --- | --- | --- |
| 点开始 | `idle` | 从第 1 拍开始，申请屏幕常亮 |
| 点停止 | `running` | 撤销未播放的点击，释放音频，回到第 1 拍 |
| 改拍号 | 任意 | 立即生效；运行时从新小节第 1 拍重新排程 |
| 改 BPM | 任意 | 立即生效；运行时从下一拍起使用新间隔，不重置小节位置 |
| 切音色 | 任意 | 立即生效；撤销未播放的点击并按原时间重排 |
| 页面隐藏 | `running` | 停止播放、关闭音频上下文、取消屏幕常亮 |
| 页面重新显示 | `idle` | 保留页面内设置，不自动播放 |

默认值：4/4、90 BPM、木质音色。小程序冷启动不恢复上次设置。

### 7.3 音频方案

`adapters/metronome-audio.ts` 使用 `wx.createWebAudioContext()`：

- 首次用户点击时创建并 `resume()` 音频上下文。
- 25ms 调度循环，每次向音频时钟提前排 120ms。
- 点击通过 `OscillatorNode`、`BufferSourceNode`、`BiquadFilterNode` 和 `GainNode` 合成。
- 三种音色参数沿用当前 PWA：木质、电子、机械。
- 重音使用原频率与音量；弱拍频率乘 0.72，并降低 6 dB。
- 记录已排程的 source 与起止时间，实现 `cancelFrom(time)`。
- 页面隐藏、停止或卸载时必须 `cancelFrom()`、停止调度器并 `close()` 音频上下文。

视觉高亮复用同一套调度结果：只在实际拍点变化时调用 `setData`，禁止每个 25ms tick 都更新页面。

### 7.4 屏幕常亮

运行时调用 `wx.setKeepScreenOn({ keepScreenOn: true })`；停止或页面隐藏时恢复 `false`。设置失败不阻止播放，但页面显示“屏幕常亮不可用”的次级提示。

### 7.5 错误状态

- 不支持 `wx.createWebAudioContext`：显示“微信版本过低，无法播放节拍器”，并禁用开始按钮。
- 音频上下文无法启动：显示“无法启动音频，请重试”，保持 `idle`。
- 播放中音频状态异常：停止并回到 `idle`，不假装仍在运行。

## 8. 调音器

### 8.1 页面结构

```text
┌───────────────────────────┐
│ [标准调弦] [自动] [开始调音] │
│                           │
│       E2   偏低 12¢        │
│   ◀────────●────────▶      │
│                           │
│ [E2][A2][D3][G3][B3][E4]  │
│                           │
│ 状态：请拨动任意一根弦       │
└───────────────────────────┘
```

- 顶部：调弦预设、自动/手动模式、开始/停止调音。
- 中部：目标音名、八度、音分读数、指针和“偏低 / 准 / 偏高”文字。
- 底部：六根弦选择器；手动模式点击后锁定目标，自动模式只显示当前识别结果。
- 半音阶模式隐藏六弦选择器，显示识别到的最近音名。
- 指针范围 -50¢ 到 +50¢；超出范围时停在端点并显示方向。
- “准”同时用文字和颜色表达，不允许只靠颜色。

### 8.2 调弦模式

- 自动模式：根据检测频率选择最近的目标弦；目标弦在预设中唯一存在。
- 手动模式：用户点击六弦之一后，音分始终相对该弦计算，即使偏差较大也不跳到其他弦。
- 半音阶模式：选择最近十二平均律音名，不显示六弦选择器。
- 切换预设时退出手动锁弦，回到自动模式。
- 切换页面或停止调音时保留当前预设和模式，但停止录音。

### 8.3 录音与 PCM 管线

页面使用 `wx.getSetting()`、`wx.authorize()`、`wx.showModal()` 和 `wx.openSetting()` 完成麦克风权限提示与设置跳转。它们属于页面交互，可直接留在页面层。

`adapters/recorder-pcm.ts` 使用 `wx.getRecorderManager()` 处理底层录音与 PCM 数据：

- 优先 `sampleRate: 48000`、`numberOfChannels: 1`、`format: "PCM"`、`frameSize: 8` KB。
- 48kHz 不可用时退回 44100、32000；实际采样率必须传入检测器。
- `onFrameRecorded` 的 ArrayBuffer 按 little-endian PCM16 转成 Float32，并归一化到 -1..1。
- 每帧先做 DC 去均值与 RMS 计算，再交给音高检测器。
- 录音时长设为 600000ms；达到上限时，如果仍在调音则自动重新启动录音。
- 停止、页面隐藏或卸载时调用 `RecorderManager.stop()`，并移除回调，避免旧帧继续更新页面。

第一版不播放参考音，避免扬声器声音被麦克风回采。

### 8.4 稳定性规则

- RMS 低于 -50 dBFS：显示“声音太小”，不更新音名。
- 清晰度低于 0.90：显示“信号不稳定”，不更新指针。
- 有效频率范围 55–400 Hz；范围外忽略。
- 最近 5 个有效读数取中位数，再用于音名和音分显示。
- `|cents| <= 3` 且连续稳定 200ms：显示“准”。
- 音分绝对值大于 3：显示“偏低”或“偏高”。
- 页面更新频率控制在每秒 10–12 次，避免频繁 `setData`。

### 8.5 状态

| 状态 | 条件 | 页面表现 |
| --- | --- | --- |
| `idle` | 未开始 | 显示预设与模式，主按钮为“开始调音” |
| `requesting` | 正在请求权限或启动录音 | 主按钮禁用，显示“正在启动麦克风” |
| `listening` | 已有 PCM 帧但未形成稳定音高 | 显示“请拨动琴弦” |
| `detecting` | 有稳定音高 | 显示音名、音分、指针和方向 |
| `denied` | 权限被拒绝 | 显示打开设置入口 |
| `error` | 录音启动失败或设备不可用 | 显示可执行的重试说明 |

页面隐藏时无论当前状态都回到 `idle`；重新显示后由用户再次点击开始。

## 9. 数据流

### 节拍器

```text
页面状态
  → guitar-core 计算下一拍与间隔
  → metronome-audio 排入微信音频时钟
  → 音频 source 发声
  → 调度循环把已到拍点写回页面状态
```

### 调音器

```text
RecorderManager PCM 分片
  → PCM16 转 Float32
  → RMS / DC 处理
  → guitar-core 音高检测
  → 无效：状态提示
  → 有效：中位数平滑
  → 最近音或手动锁弦
  → 音分与指针
```

页面不共享全局可变状态。节拍器与调音器各自在页面销毁时释放自己的适配器。

## 10. 视觉与可访问性

- 沿用现有颜色、字号层级和动效曲线；微信 WXSS 定义同名令牌。
- 播放/停止、开始/停止调音和六弦选择均使用可聚焦按钮。
- 圆盘用 Canvas 绘制刻度与指针，外层容器提供 `aria-role="slider"`、`aria-label` 和当前 BPM 文案；±1 BPM 按钮必须保留。
- 拍点不逐拍播报；只在开始、停止、权限失败和“已调准”状态变化时播报一次。
- 调音结果同时有方向文字，不依赖红绿颜色。
- 关闭动画时，拍块只换颜色，不做缩放。
- 所有页面内容避开 iPhone 底部安全区。

## 11. 验证

### 自动化

- `guitar-core` 节拍器用例覆盖拍号、重音、BPM 边界、圆盘几何和下一拍推进。
- 调弦用例覆盖三个预设的频率、音分正负、四舍五入和音名拼写。
- 音高检测用例使用 48kHz 合成波形，覆盖六个标准弦频率、±30 音分偏移、带谐波波形、静音和噪声。
- PCM 转换用例覆盖 little-endian 16-bit、静音、正负峰值和非法长度。
- 微信适配器用可注入的假 `wx` 对象测试创建、启动、停止、异常与清理。
- 运行 `npm run typecheck && npm test && npm run build`，确保 Web 现有门禁不被破坏。

### 微信开发者工具与真机

- 基础库 2.19.0 与当前稳定版各跑一次。
- 节拍器连续 15 分钟，切换 BPM、拍号和音色时无旧点击漏出。
- 切后台、锁屏、返回前台后确认声音已停止，开始按钮可用。
- 调音器在 iPhone 与 Android 各测一次权限拒绝、权限允许、页面隐藏和再次进入。
- 木吉他和未插电电吉他各调一次六根弦；电吉他接 Mac 声卡的测试不属于小程序验收。
- 自动模式靠近目标弦时能正确切弦；手动模式不会因偏差大而跳弦。

## 12. 实施阶段

1. 建立 `guitar-core`，迁移节拍器纯逻辑，加入调弦与音高检测测试。
2. 建立微信原生小程序壳、两个 Tab 和小程序基础令牌。
3. 完成节拍器 Canvas 圆盘、拍块、状态机与微信音频适配。
4. 完成调音器录音适配、PCM 管线和音高检测页面。
5. 完成权限、错误状态、屏幕常亮、页面生命周期与真机打磨。
6. 跑 Web 全量门禁和微信真机验收，整理发布说明。

## 13. 后续同步策略

- 业务规则、调弦数据、音高算法和共用文案进入共享层，变更后 Web、小程序、macOS 分别升级。
- 颜色、字号、间距等视觉令牌由同一份源生成 CSS 与 WXSS；页面结构不自动同步。
- Web 只改布局或桌面交互时，小程序不跟着改。
- 节拍器或调音器发生跨端产品改版时，先更新设计规格，再分别实现和验收。

## 14. 已知风险

- 不同 Android 机型的录音采样率、帧大小和麦克风增益差异较大，必须真机验证并保留 44.1kHz 回退。
- 手机麦克风对电吉他低音弦的拾取较弱，调音器优先保证木吉他和未插电电吉他的可用性。
- 微信音频上下文在系统中断、来电和蓝牙切换后的行为需要在真机上验证；异常时只能停止并提示重试，不能假装继续播放。
- 基础库低于 2.19.0 的用户无法使用节拍器，发布时需在设置中声明最低基础库。
