# macOS NAM 效果链桌面端 — 设计规格

日期：2026-11-01

状态：用户已批准（2026-11-02）

范围：个人使用的 macOS 独立应用第一阶段；MyGo 原生界面 + JUCE/NAM 音频引擎

## 1. 目标

为电吉他建立一条可实际演奏的本地实时效果链：从声卡输入采集信号，依次运行本地 NAM 模型与 IR，再将处理后的声音送到用户选择的声卡输出。应用使用 MyGo 构建 macOS 桌面界面，音频设备管理与实时 DSP 保持在原生 C++ 引擎内。

成功标准：

- 在 macOS 上可启动独立 `.app`，选择输入设备、输入通道和输出设备，并显示设备状态与输入电平。
- 可加载本地 NAM 模型与 WAV 格式 IR，构建、重排、旁通和保存串联效果链。
- 吉他输入经过完整链路后能实时监听，默认以 48 kHz 引擎率和 128-sample 设备缓冲启动；可调缓冲并能发现设备或模型错误。
- 重启应用后可打开本地预设；丢失或移动的模型文件会显示明确的重新定位入口。
- 现有 Next.js 静态站点和微信小程序继续独立工作，不依赖桌面端构建。

## 2. 范围

### 做

- macOS 独立应用，首轮面向当前 Mac 架构。
- MyGo 原生 UI；Go 层负责窗口、设置、链路编辑和状态呈现。
- 原生 C++ 音频引擎，使用 JUCE 管理 CoreAudio 设备与实时处理，并复用 NeuralAmpModelerCore / NAM A2 处理能力。
- 本地文件导入：NAM 模型与 WAV IR；不要求账号或网络连接。
- 串联模块：NAM 模型、IR、模块旁通、模块顺序、模块输入/输出增益和主输出增益。
- 本地预设，保存有序模块、参数与模型文件路径。
- 声卡输入/输出选择、输入通道选择、缓冲设置、输入电平与削波提示、运行/停止状态。

### 不做

- TONE3000 云 API、社区目录浏览或云端账号。
- 鼓伴奏、音高/和弦识别、TAB 自动评分或虚拟指板反馈。
- VST/AU 插件宿主模式或 DAW 工程集成；第一版只做独立应用。
- 立体声双链、并联/分支路由、MIDI 映射、录音和音频导出。
- 独立实现的延迟、混响、合唱等传统 DSP 效果。此阶段可用 NAM 模型加载已捕获的踏板或器材；后续再新增独立效果模块。
- 模型文件托管、同步或自动下载；预设只引用本地文件。

## 3. 关键约束

- 桌面端作为根目录下独立的 `desktop/` 子项目。当前小写 `app/` 是 Next.js 路由，不承载 MyGo 代码。
- MyGo 只负责 UI 与非实时控制。MyGo 自带音频播放 API 不进入吉他监听链。
- 音频回调、NAM 推理、IR 卷积和重采样都在 C++ 音频线程完成。Go UI 线程不得阻塞音频线程；实时回调不得调用 Go、访问磁盘或等待锁。
- MyGo 使用其原生 UI 路径；Go 通过 `purego` 调用同进程内 C ABI 动态库。桌面构建需把引擎 `.dylib` 打包进 `.app` 资源。
- NAM 模型和 IR 由用户从本地选择。预设保存路径，不复制、打包或改写模型内容；文件失效时保留模块信息并允许重新定位。
- 首版输入为单声道吉他通道，输出为双声道监听。引擎内部以 48 kHz 处理，设备不匹配时由音频层重采样。
- 首版以 A2 本地模型为主要验收对象；旧模型仅在所用 NeuralAmpModelerCore 版本原生支持时加载，不做专门兼容界面。
- 模型文件本身按各自许可使用。第一阶段不访问 TONE3000 服务。

## 4. 架构

```text
desktop/
├── Go / MyGo native UI
│   ├── 主窗口与链路编辑
│   ├── 设备、缓冲和电平状态
│   ├── 文件选择与预设管理
│   └── EngineBridge：通过 purego 调用 C ABI
└── native/
    └── AudioEngine.dylib
        ├── JUCE AudioDeviceManager / CoreAudio I/O
        ├── 固定 48 kHz 处理图与设备重采样
        ├── NAM Core 模型实例
        ├── WAV IR 卷积模块
        ├── 实时链路参数与安全切换
        └── C ABI 生命周期、设备、模块和状态接口
```

首版信号流：

```text
声卡单声道输入
  → 输入增益与电平检测
  → 有序 NAM / IR 模块
  → 主输出增益
  → 声卡双声道输出
```

Go 层只发送开始/停止、设备选择、文件路径、模块顺序和参数更新等控制消息，并以低频读取引擎状态用于界面。引擎在非实时线程加载模型与 IR；加载完成后再安全替换运行图，避免文件 I/O 和模型初始化进入音频回调。

## 5. 界面与交互

### 5.1 主窗口

- 顶部显示输入/输出设备、采样率、缓冲大小和运行状态；设备未就绪时提供直接设置入口。
- 主区是一条从输入到输出的串联链，按实际处理顺序显示 NAM 与 IR 模块。
- 空链路显示“添加 NAM 模型”与“添加 IR”两个明确入口。
- 每个模块显示类型、文件名、加载状态、旁通控制、输入/输出增益、排序与移除操作。
- 底部显示输入电平、削波提示、主输出增益和监听状态。
- 预设菜单提供新建、打开、保存和另存为；启动时不自动开始监听。

### 5.2 音频设备设置

- 输入设备、输入通道、输出设备分别列出当前可用的 CoreAudio 端点。
- 缓冲选项首版提供设备支持的 64、128、256 samples；默认选择 128，若设备不支持则选最接近的可用值并显示实际值。
- 输入权限未授予、设备拔出、设备格式改变或引擎无法启动时，停止监听并显示可执行的恢复步骤。
- macOS 应用包声明麦克风/音频输入用途说明。更改设备或缓冲时由引擎执行平滑停止、重开设备和恢复处理链。

### 5.3 视觉

- 桌面端沿用现有 Signal Bench 的读数优先方向：浅色画布、清楚的信号状态、等宽数值和克制的分隔线。
- 使用 MyGo 原生控件实现，不复用 Next.js React 组件或 CSS。
- 窗口先按桌面固定工作区设计；缩放时链路可横向滚动或换行，但不能压缩设备状态和主播放控制。
- 状态同时用文字和图形表达；输入削波、模型错误和设备丢失不能只靠颜色提示。

## 6. 链路与预设数据

内部链路以有序模块列表表示。概念结构：

```json
{
  "schemaVersion": 1,
  "engineSampleRate": 48000,
  "inputGainDb": 0,
  "outputGainDb": -6,
  "blocks": [
    { "type": "nam", "path": "/models/overdrive.nam", "bypassed": false },
    { "type": "nam", "path": "/models/amp.nam", "bypassed": false },
    { "type": "ir", "path": "/models/cab.wav", "bypassed": false }
  ]
}
```

- 预设写入用户 `Application Support` 目录中的应用专属文件夹。
- 预设只存文件路径和可编辑参数，不把大体积模型或 IR 嵌入预设。
- 模块类型、参数和预设均带 schema 版本，后续增加效果类型时可做迁移。
- 文件不可读、格式不支持或 NAM 架构无法加载时，模块保留在链路中并显示错误；应用不静默跳过该模块。

## 7. 错误与实时性

- **无输入设备**：关闭开始监听操作，提示连接或选择声卡。
- **输入授权被拒绝**：说明需要在 macOS 隐私设置允许音频输入，并提供重新检测入口。
- **模型/IR 无效或文件丢失**：显示出错模块和文件名，可重新选择文件或移除模块。
- **设备热拔出**：安全停止音频回调，保留当前链路，提示选择新设备后重启。
- **引擎过载或音频掉帧**：累计 underrun 计数并给出增大缓冲的建议；不在实时线程记录日志或刷新 UI。
- **参数修改**：通过线程安全的命令队列或原子参数传递。模块排序与模型替换在非实时线程准备新处理图，再于音频边界切换。
- **监听反馈**：建议使用耳机；第一版只提示反馈风险，不实现回声消除。

## 8. 验收

### 构建与界面

- `desktop/` 可单独构建为 macOS `.app`，MyGo UI 能启动并加载随包引擎库。
- 初次启动、权限拒绝、无设备、设备切换和引擎启动失败都有可识别状态。
- 设备、输入通道、缓冲、模块链路和预设均可通过键盘与鼠标操作。

### 音频链路

- 连接真实声卡和吉他，选择输入与耳机输出后，可听到直通信号；启动效果链后可听到 NAM/IR 处理结果。
- 在 48 kHz、128 samples 的兼容设备配置下连续演奏 15 分钟，无持续爆音、冻结或状态失配。
- 可加载至少一个 A2 NAM 模型与一个 WAV IR，并验证串联顺序、旁通、增益、删除和重排即时生效。
- 保存并重开预设后，链路顺序、参数与文件路径恢复；移动源文件后可重新定位。
- 设备拔插或睡眠唤醒后，应用不会显示虚假的运行状态；用户可重新选择设备并恢复监听。

### 回归

- 桌面端构建流程与根目录 Next.js、小程序构建隔离。
- 若改动现有 Web 或小程序文件，仍运行其项目门禁；只改 `desktop/` 时运行桌面端的构建与单元验证。
- 在真实声卡上进行人工试听。纯逻辑测试不能替代低延迟、设备重开和点击声验证。

## 9. 实施阶段

1. 在 `desktop/` 建立 MyGo macOS 原生 UI 骨架与 C ABI 桥接接口。
2. 建立 JUCE 音频引擎 dylib，完成 CoreAudio 设备枚举、选择、输入/输出和缓冲配置。
3. 接入 NeuralAmpModelerCore，完成单个 NAM 模块的实时监听与错误处理。
4. 实现模块列表、NAM/IR 文件导入、旁通、增益、重排与链路切换。
5. 实现本地预设保存/加载、缺失文件恢复和主窗口状态。
6. 在用户的 Mac 与声卡上进行延迟、稳定性和音质验收。

## 10. 已知风险

- TONE3000 插件的处理器、JUCE 设备层和独立 UI 当前组成完整应用；抽出无界面的 C ABI 音频引擎需要确认其模块边界，可能需要把部分 processor 生命周期封装重整。
- Go 与 C++ 的 ABI、错误返回、字符串和音频设备状态需要固定接口定义；所有实时 DSP 必须保持在 C++ 线程。
- 不同声卡对输入通道、采样率与缓冲的支持不同；实际 round-trip 延迟取决于设备和系统配置，规格不承诺统一毫秒数。
- JUCE 与 NAM Core 的依赖版本、编译选项和 macOS 代码签名/麦克风权限需要在首轮构建验证。
- 用户移动模型文件会使预设路径失效；首版采用显式重新定位，不复制或镜像模型库。

## 11. 技术依据

- [MyGo 音频文档](https://github.com/egoist/mygo/blob/main/docs/audio.md)：当前音频包面向应用播放，设备使用系统默认输出并采用较大的预缓冲；不作为吉他监听引擎。
- [MyGo 架构文档](https://github.com/egoist/mygo/blob/main/docs/architecture.md) 与 [原生库打包文档](https://github.com/egoist/mygo/blob/main/docs/distribution.md)：MyGo 通过 `purego` 调用原生 API，并支持按平台打包动态库。
- [TONE3000 Plugin 源码](https://github.com/tone-3000/tone3000-plugin)：JUCE/C++ 独立应用，包含 NAM 与 IR 信号链、设备设置和本地模型加载实现，可用于复用评估。
- [NAM A2 官方指南](https://www.tone3000.com/guides/nam-a2-the-complete-guide)：A2 架构、兼容要求及 NeuralAmpModelerCore 集成说明。
